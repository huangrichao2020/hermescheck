# hermescheck Twitter/X Launch Kit

Use this file as the public posting base for `hermescheck` releases. Keep the
message centered on `hermescheck`; mention `agchk` only as prior art when it is
useful context.

## Positioning

`hermescheck` is a Hermes Agent-focused architecture health-check tool for
stateful AI agents. It scans for runtime contracts, restart continuity, memory
freshness, cognitive architecture impact, gateway/tool boundaries,
observability, and release evidence.

## Short Post

`hermescheck` 1.4.0 is out.

It now checks whole-system cognitive architecture impact.

- cognition is not just memory; it runs across device, runtime, stores, chat, docs, cron, dream, and learning loops
- self-changing agents need an impact matrix before touching their own behavior
- source-of-truth movement must be explicit
- user-visible behavior and background-loop behavior must be reviewed together
- restart/offline failure modes are architecture, not ops afterthoughts

This release folds the newest GA/Hermes cognition lessons into `hermescheck`:
agent architecture should be audited as a living system, not a single prompt
or memory database.

## Thread Draft

1. `hermescheck` 1.4.0 is out. The core idea: serious agent cognition is a
   whole-system architecture problem.

2. A cognitive agent is not one prompt or one memory store. It spans device/OS,
   runtime substrate, execution layer, sqlite/files, brain/wiki, chat, docs,
   cron, dream, and learning loops.

3. `hermescheck` now flags cognitive systems that name memory layers but lack a
   whole-system impact matrix, source-of-truth contract, or restart/offline
   failure-mode review.

4. The audit question is practical: if the Mac sleeps, Feishu reconnects, cron
   fires, Rust accelerates a path, or a learning loop proposes self-change, does
   cognition stay coherent?

5. This is a step from local memory governance to whole-system cognitive impact:
   affected layers, source-of-truth movement, user-visible behavior,
   background-loop behavior, and failure modes.
